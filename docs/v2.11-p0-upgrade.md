# v2.11 P0 全链路升级：HITL、反馈与患者纵向管理

## 1. 本版目标

本版优先补齐医疗 CDSS 的三个产品闭环，而不是继续增加孤立功能：

1. **会诊结果必须可复核**：AI 生成正式报告前可挂起，由医生批准或携意见驳回。
2. **医生反馈必须可沉淀**：每条 AI 回答可提交结构化反馈，形成后续评测与知识修订的数据入口。
3. **患者管理必须纵向连续**：从患者建档、绿道评估、AI 意见到随访结局形成一条时间线。

## 2. 新增能力

### 2.1 HITL 医生复核闭环

- 前端输入区新增「🛡 复核」开关，默认开启。
- Python LangGraph 在生成报告前触发 `human_review` interrupt。
- Java 收到 `human_review` 事件后：
  - 创建 `clinical_review_task` 复核任务；
  - 将共识、综合提案、关键风险等 payload 透传前端；
  - 支持刷新页面后从历史接口恢复待复核卡片。
- 前端复核卡片支持：
  - 批准并生成最终报告；
  - 填写意见后驳回，重新进入专家会诊；
  - 连续驳回/再次挂起；驳回后清空本轮决定，重新会诊完成并再次通过校验后会重新发起医生复核。
- 批准后最终报告通过 `POST /api/clinical-reviews/{taskId}/resume` 流式返回并落库到原对话。

相关接口：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/clinical-reviews/pending` | 当前医生待复核任务 |
| GET | `/api/clinical-reviews/by-talk/{talkId}` | 查询指定对话待复核任务 |
| POST | `/api/clinical-reviews/{taskId}/resume` | SSE 续跑：批准/驳回并生成回答 |

### 2.2 AI 回答医生反馈

- 每条 AI 回答底部增加「👍 有帮助 / 👎 需改进」。
- 「需改进」支持选择分类并填写说明。
- 反馈写入 `doctor_feedback`，包含医生、对话、评分、分类、说明和回答摘要。
- 提供反馈汇总接口，便于后续接入质量看板。

相关接口：

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/feedback` | 提交回答反馈 |
| GET | `/api/feedback/summary` | 当前医生反馈汇总 |

### 2.3 患者随访与结局

- 支持为患者创建门诊/电话/微信/其他类型随访。
- 支持录入 mRS、卒中复发、服药依从性和随访记录。
- 随访状态：`PENDING`、`COMPLETED`、`CANCELLED`。
- 所有数据按当前医生隔离，并校验患者归属。

相关接口：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/patients/{patientId}/followups` | 随访列表 |
| POST | `/api/patients/{patientId}/followups` | 创建随访任务 |
| PUT | `/api/patients/{patientId}/followups/{followupId}/complete` | 录入随访结局 |
| GET | `/api/patients/{patientId}/followups/summary` | 待随访汇总 |

### 2.4 患者纵向时间线

时间线聚合：

- 患者建档与档案更新；
- 急诊绿道评估；
- AI 风险分析；
- 健康数据更新；
- 随访任务与随访结局。

接口：`GET /api/patients/{patientId}/timeline`

前端在患者详情中直接展示，无需切换页面。

## 3. 数据表

新增 Flyway 迁移：

- `V4__add_review_feedback_followup.sql`：

  原列表中的三张新表由该迁移创建：

- `clinical_review_task`：医生复核任务、决策、意见与最终报告；
- `doctor_feedback`：AI 回答反馈；
- `patient_followup`：随访任务与卒中结局。
- `V5__fix_patient_timestamps.sql`：修复旧版 `patient` 表时间字段为 VARCHAR 且历史为空导致患者时间线缺少建档事件的问题，转换为 `DATETIME` 并补充默认值。

## 4. 关键安全约束

- 所有复核任务、反馈和随访接口均由当前登录医生身份访问。
- 复核任务只允许任务所属医生读取和续跑。
- 反馈提交前校验对话归属。
- 随访任务创建/完成前校验患者归属。
- 患者时间线只聚合同一医生名下患者的数据。
- HITL 驳回必须填写意见，避免无信息返工。
- AI 输出仍为辅助参考，最终报告需医生批准。


3. 绿道实时预警、团队任务板与通知中心；
4. DICOM/PACS、影像 AI 与真实 FHIR 字段映射；
5. 用药安全引擎、抗凝逆转与再灌注决策卡；
6. 全链路 OpenTelemetry、AI 质量看板与临床专家盲评。
